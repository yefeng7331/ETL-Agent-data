# 后端全链路流程：连接登记至受管回滚

- 状态：v0.2 文档基线及前五项后端功能已获用户验收；D-56 至 D-59 规则已确认。本文是流程展开，不是独立需求基线。真实联调与运行验收另见实施状态。
- 权威：首版业务规则、技术约束与验收均以 [MVP_SPEC](MVP_SPEC.md) 为准；完整产品目标见 [PRD](../PRD.md)。已确认选择见 [DECISIONS](DECISIONS.md)，实现证据见 [IMPLEMENTATION_STATUS](IMPLEMENTATION_STATUS.md)。
- 范围：首版 MySQL 订单/用户 → Doris 宽表，周期增量批处理，真实组件测试环境和非敏感数据。Web 控制台的具体路径、字段和错误语义见 [接口契约](API_CONTRACT.md)；本文按业务顺序说明服务端状态与内部交接。

## 1. 身份、连接与受管探查

1. 首版用管理员命令行初始化本地具名账户、项目和成员关系；密码交互输入且只存安全哈希，按已确认的长度与离线弱密码规则校验。登录采用安全 Cookie、CSRF 及服务端会话：空闲 15 分钟或累计 8 小时失效，单账户 15 分钟内连续失败 5 次后限制登录 15 分钟。FastAPI 对每个显式携带项目标识的业务请求校验租户、项目、角色与资源范围；工作台可返回操作权限清单，但不是授权来源。Maker 只从项目内授权别名选择管理员预置的 Vault KV v2 Secret 引用，登记 MySQL 源及 Doris 目标，不提交或读取凭据明文。缺少引用时可保存未就绪连接草稿：只接收名称、类型、主机、端口和数据库名，项目 Maker 每次读写均重新鉴权，创建或修改与具名审计同事务；后端不得发起连通性测试或探查。经授权的探查 Worker 临时取得最小权限凭据；控制面仅保存引用，界面、日志、报告和审计不得泄露明文。
2. 引用就绪后，后端把连通性、Schema 与安全统计探查交给异步任务，再判定字段分类状态。未分类字段可返回 Schema 和安全统计，但暂停返回其样本值；探查失败或越权则保留失败事实，不将连接或 Profile 标为可用。Maker 可提出分类及脱敏建议并提交安全审批人待办；确认绑定字段和 Schema 版本，仅新增或变化字段重审。具名安全审批人必须在 Prepare 前确认分类和脱敏规则，未确认则 Prepare 阻断。
3. 探查结果及分类状态交给 [需求生成与版本冻结](FLOW_01_DESIGN_FREEZE.md)。探查只读，且受授权约束；它不构成目标端试运行或数据发布。

接口交接：登录后查询项目与工作台；当前工作台只提供已实现操作的 `allowed_actions`、Maker 的本项目草稿数量与入口，并明确标出未接入概况，不以零替代。Auditor 可分页读取本项目连接创建/修改审计事件，仅含非密标识；查询时重新核对项目角色，不返回连接详情。后续 Maker 查询授权别名、保存连接草稿、发起探查并查询任务/Profile；分类建议和安全审批决定分别落在可追溯记录。页面超时后查询任务或 Profile 实际状态，不能以断线推断探查失败。

## 2. 设计、校验与不可变版本

1. LangGraph 接收 Maker 的订单/用户宽表需求及已授权 Profile，建立可恢复的澄清会话并以异步任务生成候选。缺少去重、关联、字段映射等关键语义时中断并保存 Checkpoint；Maker 补充后恢复，并用会话修订版阻止并发回答互相覆盖。模型可自动修复语法、格式等**不改变业务语义**的问题；映射、去重、过滤或资源范围变化须 Maker 重新确认。
2. 后端生成 EtlPlan 与 SeaTunnel HOCON 候选，先提供独立静态校验，再在 Maker 显式冻结时重跑确定性语法、Schema、字段分类与映射门禁。审批前所谓“试运行”仅包括静态校验和已授权的只读安全探查；不得启动会写入 Doris 的 SeaTunnel 作业。
3. MySQL 订单表与用户表均须具备主键、可靠变更标记及软删除标记；任一缺失就阻止 `PipelineVersion` 冻结并指出缺项，不以全表读取降级绕过。用户记录变化须使该用户的**全部历史订单**在下一完整宽表版本中更新；软删订单从当前宽表移除，软删用户的历史订单保留订单事实、用户维度字段置空并标记删除。
4. 门禁通过且 Maker 确认后，后端冻结不可变 `PipelineVersion` 与 SHA256 摘要。候选或关键事实变化时生成新版本；已冻结版本交给 [准备单与审批执行](FLOW_02_APPROVAL_COMMIT.md)，不得沿用旧审批。

接口交接：当前 Maker 只可保存、读取、修改本项目非执行 Pipeline 草稿，引用本项目未就绪 MySQL 源和 Doris 目标，填写订单/用户表及周期说明文字；写入同事务留审计。周期文字不触发排程，拟议阈值和预算明确未填写。后续须先确认周期触发/时区/漏跑规则及阈值、预算字段口径与审批流程，方可接入 Maker 提议、澄清会话、候选、静态校验和冻结；当前没有这些接口的可用业务链路。未来会话版本冲突、候选失效或门禁失败均返回可恢复的实际记录，不覆盖已冻结事实。

## 3. 每轮 Prepare 与独立审批

1. 首轮由 Maker 发起 Prepare；此后 Celery Beat 按冻结周期为**每一轮**发起受管 Prepare，生成待审准备单，不自动 Commit。Maker 提议该 Pipeline 的质量阈值和预算；服务端冻结本轮输入/版本指纹、增量水位上界与资源范围、已确认的分类和脱敏规则、影响范围、预算、回滚目标、审批职责及质量阈值；事实缺失则停在待补/失败状态。Prepare 不产生目标端写入。后轮单可创建及审批，但前轮未执行或未受管关闭前不得先行 Commit；前轮发布改变已发布水位后，后轮若冻结范围过期须重新 Prepare 和审批。
2. PDP 对照 SPEC 已确认的 P0–P3 触发条件取最高等级。P0 禁止越权、敏感信息暴露和治理绕过；P1 管制 Commit、L2 实写、发布及发布后回滚；P2 管制授权在线只读探查与有界脱敏样例；P3 适用于授权静态或缓存元数据。无法判定或证据不足则阻断，由安全责任人补足规则并重新 Prepare；附加控制不得减免 Commit 的双人审批。
3. 两名**不同的具名**数据审批人和安全审批人，均非本次 Maker，可基于**同一份不可变 Preparation**并行、独立给出决定。服务端绑定身份、角色、决定和准备单指纹；拒绝、缺席、越权、同人兼任或事实变化均不可 Commit。任一变更须重新准备并重新取得两项批准。

接口交接：统一队列与详情返回本轮冻结证据和两项独立决定；审批提交由后端确定账户职责并绑定同一指纹。驳回或失效从原单生成新单，原决定只读；拒绝、失效或超时后页面查询准备单事实。受管关闭不得推进已发布水位。

## 4. Commit、授权与可靠投递

1. 具备权限的 Operator 发起 Commit；服务端复核 `PipelineVersion`、Preparation、轮次顺序、风险结论、两项审批、项目权限和事实时效。**Preparation ID 是幂等边界，同一 Preparation 最多对应一次实际 ExecutionRun**；重复请求或超时重试返回已有运行/拒绝结果，不重复签发执行或投递。要再次运行，须新 Prepare 和新双人审批。
2. 复核通过后，服务端签发绑定主体、工具、环境与制品指纹的 Ed25519 单次 Capability（5 分钟有效）。Tool Broker 与 Replay Guard 检查授权及重放；`ExecutionRun` 和 Outbox 命令在同一事务落库。事务失败不产生有效执行，投递重试也不得扩大为第二次运行。
3. Celery Worker 消费受管命令并验签，授权执行时才临时物化 Vault Secret，向 SeaTunnel Zeta 提交作业，记录作业 ID、状态、审计证据。验签、凭据或提交失败时保持准确失败状态；“已提交”不等于“已运行”或“已发布”。

接口交接：Commit 首次受理返回 `ExecutionRun` 引用，重复提交返回相同运行或原拒绝事实；前端通过运行查询恢复，不能凭 HTTP 超时再次制造新运行。Worker、Tool Broker 和 SeaTunnel 的交接是内部受管命令，不由浏览器直接调用。

## 5. 增量搬运、宽表重建与质量阻断

1. SeaTunnel 按 Prepare 冻结的水位上界搬运 MySQL 订单与用户增量到 **Doris 暂存区**，并反馈行数、字节数、时长及错误。Doris 在目标端关联暂存增量与所需历史数据，生成**完整的待发布影子宽表**；变更用户须影响其全部历史订单。软删订单从当前宽表移除，软删用户保留历史订单事实、用户维度字段置空并标记删除。SeaTunnel 负责搬运，Doris 负责关联与完整版本构建，FastAPI/Celery 负责授权、状态和监督。订单与用户变化须有提交顺序可靠的单调标记，且从一致快照冻结共同上界；迟到或并发变化无法可靠归属时阻断本轮发布。
2. 仅行级格式或值异常可依据 Preparation 已冻结的 Pipeline 拒绝阈值分流到错误表，并保留错误码、原因和可审计统计。安全暴露、Schema、主键、映射及完整性错误直接阻断；不能计入“可接受脏行”后继续发布。低于阈值也须通过其他全部门禁；质量报告未通过、预算超限、任务异常或影子版本不完整时硬中断并禁止发布。
3. 后端形成 `QualityContract` 与 `RuntimeSupervisionContract` 判定、失败快照、可解释诊断及 Evidence Ledger 记录。页面只显示服务端确认的状态。质量结论和影子版本交给 [运行质量与回滚](FLOW_03_RUNTIME_ROLLBACK.md)的发布步骤。

接口交接：运行查询分别提供作业、质量和发布阶段；质量明细仅向额外获授权角色提供有界、脱敏且可审计的样例查看/下载。Operator 中断时由后端停止作业、阻止发布、清理未发布暂存及影子结果；页面通过同一运行与中断记录查询实际收尾状态。

## 6. 自动发布、版本保留与受管回滚

1. 本轮 Commit 已获有效授权且全部质量和完整性门禁通过时，后端自动发起受管发布；Doris 将待发布影子宽表原子换为正式表，后端核实正式版本并记录结果，随后才推进已发布水位。不另设人工发布批准，也不得把“质量通过”提前显示为“已发布”。
2. 保留**当前正式版和紧邻上一正式版**以支持发布后回滚。发布失败时以目标端实际正式表状态为准，不能推定成功；未发布影子版本进入受管清理路径。更旧版本的自动清理推迟；保留期、存储预算和审批规则确认前不得实现清理。
3. 具备权限的 Operator 可发起受管回滚，无须重新走双人审批；先预览当前正式版、上一版和影响，再将预览操作 ID、所见版本与原因提交。后端核验项目、权限、目标与当前正式版本，并按最小授权执行；发布和回滚按 Pipeline 串行，版本变化时拒绝旧预览，重复提交返回同一回滚记录。发布前回滚清理未发布影子版本；发布后使用紧邻上一正式版反向原子换表，将水位恢复至上一正式版对应值、失效旧准备单，后续以新 Prepare 和双审批重放。回滚中、成功或失败均记录证据，失败时返回目标端实际正式版本，不把错误版本重新发布。

接口交接：发布状态单独查询；回滚预览无换表副作用，提交后查询回滚记录与真实正式版。L2 Benchmark 若产生写入，仅在隔离的非敏感测试资源，经普通 Prepare、双审批、Operator Commit 和审计链路执行；评测申请接口不得直接触发写入。

## 状态交接与失败原则

`Connection/Profile → Candidate → PipelineVersion → Preparation → 双审批 → ExecutionRun/Outbox → SeaTunnel 暂存 → Doris 待发布宽表 → QualityReport → 正式版/回滚`

每一步先读取并复核上一步的不可变事实，再推进服务端状态；缺失、失效、越权或重复请求保持可解释的停留/失败状态。接口返回稳定业务错误码、可展示原因、请求追踪标识与相关记录引用，敏感内部细节只留在受控日志。所有可见状态来自后端事实，前端不物化 Secret、不直接提交 SeaTunnel、不判定审批/质量，也不执行换表。前端连续操作见 [前端全链路流程](FRONTEND_END_TO_END_FLOW.md)；具体页面交接分别见 [流程一](FLOW_01_DESIGN_FREEZE.md)、[流程二](FLOW_02_APPROVAL_COMMIT.md)、[流程三](FLOW_03_RUNTIME_ROLLBACK.md)。
