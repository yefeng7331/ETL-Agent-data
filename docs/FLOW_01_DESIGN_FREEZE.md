# 流程一：需求生成与版本冻结

状态：文档已验收；功能与运行验收另见实施状态。

权威规则见 [MVP_SPEC](MVP_SPEC.md)；前端连续操作见 [前端全链路流程](FRONTEND_END_TO_END_FLOW.md)，后端连续交接见 [后端全链路流程](BACKEND_END_TO_END_FLOW.md)。本文件只展开页面、服务端和交接行为，不新增需求或接口格式。

| 步骤 | Vue 页面操作与可见状态 | FastAPI／后端职责与交接 | 失败反馈 |
| --- | --- | --- | --- |
| 1. 连接与 Profile | Maker 在当前项目登记 MySQL/Doris Secret 引用；无可用引用时保存未就绪草稿，探查不可用。引用就绪后查看 Schema、安全统计及获准的脱敏样本；未分类字段的建议提交给安全审批人待办。 | 控制面校验项目角色与资源范围；草稿不触发探查。授权探查 Worker 临时物化最小权限凭据；未分类字段暂停样本返回，安全审批人于 Prepare 前确认分类和脱敏。 | 连接、越权或探查失败时不把 Profile 标为可用；草稿与未分类项标明阻断原因，不暴露凭据和样本明文。 |
| 2. 需求与澄清 | Maker 输入自然语言需求并填写源表、目标、周期等关键项；问题与回答保存为草稿，离开或重登后从工作台续答。 | LangGraph 保存对话和工作流状态；缺少去重等关键参数时中断，收到 Maker 补充后从 Checkpoint 恢复，并把当前状态交给页面。 | 中断未完成或恢复失败时保持待澄清／失败状态，不把未确认参数带入冻结版本。 |
| 3. 候选与门禁 | 展示 EtlPlan、HOCON、DAG、字段映射／Diff、候选历史和校验错误；语义不符时 Maker 提出修改要求并查看新候选差异。 | 后端生成新候选并执行确定性语法、Schema、主键、可靠变更标记和软删标记门禁。模型仅自动修复非语义的语法/格式错误；审批前“试运行”只含静态校验与授权只读安全探查。 | 缺任一必需标记或门禁失败时指出缺项并阻止冻结；不得改走全表读取或提前写入 Doris。 |
| 4. 版本冻结 | 门禁通过后，Maker 核对源表、关联和更新规则、目标、周期、安全限制及相对上版差异，显式确认；页面区分可冻结、已冻结与已提交。 | 后端冻结不可变 `PipelineVersion` 和 SHA256 摘要，关联已确认的周期增量、水位、质量规则及目标；用户变更须覆盖其全部历史订单。冻结版本交给[准备单与审批执行](FLOW_02_APPROVAL_COMMIT.md)。 | 冻结／提交失败时显示实际状态；需求、映射或策略变化须生成新候选和摘要，不沿用旧审批。 |

页面至少区分待澄清、生成中、校验失败、可冻结、已冻结、已提交；异步生成按任务查询，并发续答版本冲突时重读服务端会话。候选先独立校验，Maker 再显式冻结，后端冻结前重验；状态以服务端事实为准。此阶段不由浏览器直接连接 SeaTunnel 或物化 Secret。软删订单从当前宽表移除，软删用户保留历史订单事实、清空用户维度字段并标记删除。订单和用户变化须有提交顺序可靠的单调标记；源端一致快照及共同上界无法验证时阻断冻结或后续发布，不猜测迟到变化归属。接口交接见 [接口契约](API_CONTRACT.md)。
