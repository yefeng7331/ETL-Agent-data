# 流程二：准备单、审批与执行授权

状态：文档已验收；功能与运行验收另见实施状态。

权威规则见 [MVP_SPEC](MVP_SPEC.md)；前端连续操作见 [前端全链路流程](FRONTEND_END_TO_END_FLOW.md)，后端连续交接见 [后端全链路流程](BACKEND_END_TO_END_FLOW.md)。本流程接收已冻结 `PipelineVersion`，向[运行质量与回滚](FLOW_03_RUNTIME_ROLLBACK.md)交接受管执行事实。

| 步骤 | Vue 页面操作与可见状态 | FastAPI／后端职责与交接 | 失败反馈 |
| --- | --- | --- | --- |
| 1. Prepare | 首轮 Maker 从冻结版本发起；后续每轮查看 Beat 自动生成的待审单。统一队列按 Pipeline 展示轮次、来源、状态和阻断原因；详情供有权限者核对影响范围、预算、回滚方案与质量阈值。 | 服务端每轮冻结输入/制品指纹、水位、资源范围、已确认的分类/脱敏、风险结论及审批职责槽；此阶段无目标端写入。 | 准备失败、分类未确认或事实不完整时显示原因，不开放审批或 Commit；Beat 不能自动执行。 |
| 2. 独立审批 | 数据、安全审批人并行查看**同一**准备单的方案差异、探查、安全证据和冻结事实，分别具名决定并填写理由；页面显示彼此状态。 | PDP 依已批准规则给出风险结论；服务端核验身份、角色、与 Maker 及彼此互异，并把决定绑定同一冻结事实。 | 无法判定 P0–P3 时阻止 Commit，待规则确认并重新 Prepare；任一拒绝、缺席、越权或事实变化也不可 Commit。 |
| 3. 驳回或失效后修订 | 原单保留只读结论和原因；Maker 从原单详情发起修订，并在新单中重新走双审批。 | 服务端保留原审批证据，变化后生成新 Preparation 与指纹；旧决定不迁移。 | 原单不可覆盖或直接重提；修订失败时显示原因，不开放 Commit。 |
| 4. Commit 复核 | Operator 核对准备单版本、审批人和本轮执行摘要后显式确认；提交期间锁定重复操作，页面显示请求中、拒绝、既有结果或已接受状态。 | 服务端重新核验版本摘要、准备单、风险结论、审批事实与权限；同一 Preparation 最多一个实际 `ExecutionRun`，重复/超时重试返回既有结果。 | 事实失效或权限不足时拒绝并说明重新准备/审批；超时后从原单读取结果，重复 Commit 不产生第二次执行。 |
| 5. 授权与投递 | 页面显示 `ExecutionRun` 及投递状态，并进入[运行中心](FLOW_03_RUNTIME_ROLLBACK.md)查看后续结果；“已提交”不表示作业成功。 | 后端签发受限 Capability，经 Tool Broker／Replay Guard 验证，在同一事务写入 `ExecutionRun` 与 Outbox；后续由 Celery Worker 消费并执行。 | 验签、重放、过期或事务失败时不得产生有效执行；显示实际拒绝／失败状态，不伪报为运行成功。 |

页面应区分待准备、待数据审批、待安全审批、拒绝／失效、可 Commit、已提交。Maker 提议的质量阈值和预算须在首轮 Prepare 前取得数据、安全审批人批准，并在每轮准备单冻结；数值缺失阻断 Prepare。后轮可准备和审批，但前轮未执行或未受管关闭前不得 Commit。只有 Operator 可对已拒绝、失效、失败或中断的前轮准备单执行受管关闭：须有原因、无活跃运行或发布、留审计且不推进水位。Prepare 冻结增量上界，成功发布后才推进水位；过期范围须新准备单与新审批。凭据物化与执行授权均由后端受管完成，浏览器不直接触发 SeaTunnel。P0–P3 按 SPEC 已确认规则判定；无法判定时阻断，不得减免 Commit 的两名独立具名审批。接口交接见 [接口契约](API_CONTRACT.md)。
