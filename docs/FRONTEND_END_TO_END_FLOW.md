# 前端全链路流程：登录至受管回滚

- 状态：v0.2 文档基线及前五项后端功能已获用户验收；页面验收另见实施状态。本文展开首版 Vue 控制台的角色操作、可见状态、交接和失败反馈，不是独立需求基线。
- 权威：首版范围、业务规则与验收以 [MVP_SPEC](MVP_SPEC.md) 为准；服务端连续交接见 [后端全链路流程](BACKEND_END_TO_END_FLOW.md)，请求和错误语义见 [接口契约](API_CONTRACT.md)。本文不另定接口路径、数据格式或未确认的阈值。
- 范围：MySQL 订单／用户至 Doris 宽表的周期增量场景。下述页面均为待实现设计，目前无可运行前端或用户验收证据。

## 1. 登录、选项目与工作台

1. 用户以本地具名账户登录后先明确选择项目；页面持续标明当前项目，并允许在有权访问的项目间切换。切换后重新读取该项目的数据和待办，不沿用上一项目的操作上下文。
2. 统一项目工作台按服务端返回的当前项目 `allowed_actions` 显示导航；现有后端返回当前项目、已实现操作、Maker 可见的本项目未就绪连接草稿数量和入口，以及 Auditor 的本项目连接审计读取操作。非 Maker 的连接概况为 `null`；Pipeline、准备单、运行和待办由 `unavailable_sections` 标为未接入，页面不得显示为零。后续接入真实记录后，各角色再从获授权的记录进入流程。服务端始终逐次校验项目、角色、资源范围，不以导航清单授权。
3. 待审批准备单、运行失败和回滚结果在工作台形成站内待办或状态提醒，点击后进入对应记录。首版不依赖外部消息渠道；页面不把未读取的状态推断为已完成。

## 2. 连接、探查与字段分类

1. Maker 从项目内获授权的 Vault 凭据别名中选择 MySQL 源及 Doris 目标的受管连接引用。管理员尚未提供可用别名时，可保存**未就绪草稿**并看到缺项；草稿只输入名称、MySQL 源/Doris 目标类型、主机、端口和数据库名，页面不提供用户名、密码、Vault 路径或任意扩展字段。连通性测试、探查及后续依赖该连接的操作不可用。仅项目 Maker 可读写草稿，页面不要求输入或展示凭据明文。
2. 引用就绪后，Maker 发起受授权的连通性测试和只读 Schema／安全统计探查；页面以异步任务和 Profile 的服务端记录区分草稿、探查中、可用和失败。未分类字段仅显示允许的 Schema 与安全统计，暂停样本返回。
3. Maker 在资产页查看未分类字段，提出分类及脱敏建议并提交给安全审批人；安全审批人的项目待办展示待确认字段、建议与受控证据。决定绑定字段和 Schema 版本，变更时仅新增或变化字段重审。确认后按权限展示允许的脱敏样本并解除相应 Prepare 阻断；拒绝或仍有未确认项时保留原因和待办。分类与脱敏的最终判定由后端核验，不由页面自行解除门禁。

## 3. 需求输入、澄清与候选方案

1. 当前后端仅支持项目 Maker 保存、读取、修改非执行 Pipeline 草稿：选择本项目 MySQL 源和 Doris 目标连接、订单/用户表，填写周期说明文字。草稿可引用未就绪连接；周期文字不排程，拟议质量阈值与运行预算显示未填写，页面不能提供生成、冻结或 Prepare 操作。未来 Pipeline Studio 用自然语言描述业务目标，并在关键项表单选择源表、目标和已确认的运行周期；页面提交前提示缺失项，服务端继续校验。生成中、待澄清、失败和可继续状态清晰可见。
2. 多轮澄清的问题与回答保存为草稿；生成与续答按异步任务查询。Maker 离开页面或重新登录后，可从工作台待办回到同一会话，从服务端 Checkpoint 续答。并发修改使所见会话修订版过期时，页面提示冲突并重读最新内容；恢复失败时显示实际状态，不把未确认语义带入候选或冻结版本。
3. 候选页展示 EtlPlan、HOCON、DAG、字段映射、校验结果及版本差异。Maker 发现业务含义不符时标注问题并提出修改要求，由后端生成**新候选**；页面保留候选历史与差异。涉及映射、去重、过滤或范围的语义变化仍须 Maker 重新确认，前端不把模型修复当作确认。
4. 冻结前，页面集中展示源表、关联和更新规则、目标宽表、运行周期、安全限制及相对上版差异；列明主键、变更标记、软删标记等门禁缺项。全部服务端门禁通过后，Maker 显式确认并提交冻结；页面显示不可变版本和摘要。失败候选不得进入审批，审批前试运行仅限 SPEC 允许的静态校验与只读安全探查。

## 4. 准备单、独立审批与 Commit

1. 首轮由 Maker 从已冻结版本发起 Prepare；后续每轮由 Beat 生成待审准备单。工作台的**统一准备单队列**按 Pipeline 展示轮次、来源、状态和阻断原因，各角色从同一记录进入有权操作。页面不把自动生成准备单显示为自动获批或自动执行。
2. 数据、安全审批人分别查看同一不可变准备单的方案差异、探查与安全证据、风险结论、质量阈值、预算、影响范围及回滚方案；各自独立批准或驳回并填写理由。页面分别显示两人的决定与待办状态；Maker 自批、同人兼任、缺席、拒绝或事实失效时 Commit 不可用，服务端作最终判定。
3. 驳回或失效的原单保留只读结论和原因。Maker 可从原单详情发起修订；服务端形成**新准备单**，重新取得两项审批，不在原单上覆盖既有决定。
4. 双审批有效后，Operator 在 Commit 前核对准备单版本、审批人与本轮执行摘要，再显式确认。后轮准备单虽可审批，前轮未执行或未受管关闭前仍不可 Commit；范围过期时须重新 Prepare 和审批。提交期间页面锁定重复操作并查询同一准备单的服务端结果；重复或超时重试只展示原有 `ExecutionRun` 或拒绝结果，不显示第二次运行。已提交、待执行、运行中和失败分别呈现。

## 5. 运行质量、发布与回滚

1. 运行中心按准备单和 `ExecutionRun` 展示 SeaTunnel 作业、吞吐、读写量、有效／拒绝行数、错误码、预算和诊断。页面自动定期读取最新服务端状态，标明更新时间并允许手动刷新；离开后重进可从同一运行记录继续查看。刷新间隔和接口形式留待实现设计，不在本文预定。
2. 出现脏数据或质量失败时，具备运行查看权限的角色可见计数、原因和冻结阈值的服务端判定；仅获授权角色可查看**脱敏后的行级样例**，下载同样有界、脱敏并留审计。安全、Schema、主键、映射和完整性错误按 SPEC 直接阻断；页面不自行判定质量是否达标。
3. Operator 可从运行记录发起受管中断，页面查询停止作业、禁止发布和未发布结果清理的实际状态；若已发布，则进入独立回滚流程。发布详情区分质量通过、发布中、已发布和发布失败，并展示服务端确认的本轮正式版本、紧邻上一版本与证据。质量通过不能提前显示为已发布；后端在本轮授权内自动发布，页面不提供额外人工发布门禁。
4. 有权限的 Operator 发起受管回滚前，页面预览当前正式版、可回滚目标、影响摘要，并要求填写原因及显式确认。预览绑定操作标识与所见正式版；若正式版变化，提示旧预览失效并重新预览。随后展示回滚中、成功或失败和服务端核实的实际正式版本；发布前清理与发布后恢复的业务规则以 SPEC 为准。前端不直接操作影子表或执行 Swap。
5. 审批、Commit 或回滚提交后如遇超时或断线，当前记录显示“结果待确认”；恢复后读取对应准备单、运行或回滚记录的服务端最终状态，支持手动刷新，避免仅凭网络错误推断操作未生效或盲目重复发起。

## 6. 审计、Benchmark 与设计输入

1. 当前后端仅支持 Auditor 查询本项目连接创建、修改事件的非密标识，尚无对应前端页面。未来有权限的角色可按项目、Pipeline、轮次和操作者追溯审批、Commit、发布、回滚记录及 Benchmark 结果，并从记录进入相应证据；只显示其获授权的内容。安全治理页保留 SPEC 规定的授权触发版本化 L0／L1／L2 评测及结果展示；L2 实际写入的申请仍进入普通准备单、双审批和 Operator Commit 页面，不以评测请求绕过门禁，也不以报告展示宣称达到尚未确认的阈值。
2. 后续视觉设计以用户提供的 pen.dev 画板样例为输入。当前未取得具体画板，不规定颜色、布局、组件款式或响应式细节；视觉稿和实际页面仍须单独核对。

## 交接与核对

页面动作与服务端状态始终按 `项目 → 连接/Profile → 候选 → PipelineVersion → Preparation → 双审批 → ExecutionRun → 质量报告 → 正式版/回滚` 串联。前端只发起获授权操作并展示服务端事实；凭据物化、审批判定、执行授权、质量发布和回滚均由后端受管完成。分段责任与失败路径见 [流程一](FLOW_01_DESIGN_FREEZE.md)、[流程二](FLOW_02_APPROVAL_COMMIT.md)、[流程三](FLOW_03_RUNTIME_ROLLBACK.md)。已确认风险规则、推迟的数值和进入实施前的阻断条件见 [MVP_SPEC 待确认与变更控制](MVP_SPEC.md#待确认与变更控制)。
