- 版本：v0.6；v0.2 文档基线已由用户验收，D-56 至 D-59 的分项范围由用户逐题确认
- 日期：2026-09-28

## 目标与范围

- 首版交付一个完整的 **MySQL → Doris** 场景：从订单表、用户表生成 Doris 宽表，覆盖受管元数据探查、自然语言需求澄清、EtlPlan/HOCON 生成、确定性校验、不可变版本、准备单、独立审批、受管执行、质量分流、原子发布、运行监控、审计证据和回滚。
- 采用**周期增量批处理**。每轮以水位识别增量，形成完整、可发布的宽表版本；只有该轮质量与完整性校验通过才可原子替换正式表。首版不要求连续 CDC。
- 首版在由真实 MySQL、Doris、SeaTunnel、Celery 等组件组成的测试环境，以非敏感数据完成端到端验收。生产部署与真实敏感数据接入不属于此次验收。
- 用户承担首版测试验收；PostgreSQL 测试库由用户后续提供，测试环境搭建、授权和故障排查的具名负责人尚未指定。真实环境联调前须落实对应负责人；长期生产运维负责人须在生产部署前指定。
- SeaTunnel 只把订单/用户增量搬运到 Doris 暂存区；Doris 关联增量与所需历史数据，生成完整的待发布影子宽表。用户记录变化必须使该用户全部历史订单在新版本中更新。软删订单从当前正式宽表移除；软删用户的历史订单保留订单事实，用户维度字段置空并标记用户已删除。
- 交付可运行 Vue 控制台、FastAPI 控制面、LangGraph 编排、Celery Worker/Beat、PostgreSQL/Redis 环境、SeaTunnel Zeta 集成、版本化 Benchmark 测试集及上述端到端演示链路；这些是目标。前五项账户/会话/项目权限、未就绪连接草稿、工作台现有数据、Auditor 读取本项目连接创建/修改审计事件及非执行 Pipeline 草稿功能已获用户验收。真实数据库和 HTTPS 联调未验证；其余链路未实现，见 [实施状态](IMPLEMENTATION_STATUS.md)。
- [PRD](../PRD.md) 所列其他数据库、文件、对象存储、REST API 等来源，以及第二个脏日志演示场景，属于完整产品目标，不作为首版端到端验收范围。首版只接入一个在实现前明确选定的模型 Provider；多 Provider 适配推迟。安全策略首版只支持版本化 Benchmark、证据和人工审核后启用的规则；模型自主修改或启用策略推迟，进入实施前须另定授权、审核和回滚门禁。

## 角色与业务规则

- 用户需经认证鉴权，在隔离的租户项目内按成员角色访问；`Maker`（数据工程师）登记连接、发起只读探查、描述需求、确认澄清与候选方案、提交冻结版本；不得审批自己的申请。
- 首版使用本地具名账户和项目角色。管理员通过受管命令行初始化测试账户、项目及成员关系，交互输入密码且只保存安全哈希，不开放自助注册。单因素密码至少 15 字符、允许至少 64 字符；以离线版本化公开弱密码表及账户/项目上下文拒绝常见或已泄露密码，不强制字符组合或定期改密。服务端会话空闲 15 分钟、最长 8 小时；单账户 15 分钟内连续失败 5 次后限制登录 15 分钟，登录失败统一提示，不暴露账户存在性。Web 控制台通过服务端会话、安全 Cookie 和 CSRF 防护调用 FastAPI。业务请求显式携带项目标识，由后端逐次校验项目及资源权限；工作台返回可执行操作清单供页面展示。管理员预置 Vault KV v2 凭据并提供项目内授权别名，Maker 只选择别名登记引用，不接触 Vault 原始路径或明文。未分类字段允许返回 Schema 和安全统计，但暂停返回样本；安全审批人须在 Prepare 前确认分类和脱敏规则。分类确认绑定字段和 Schema 版本，仅新增或变化字段重新待审。
- 登录后用户先选择有权访问的项目，工作台持续标明当前项目并按角色显示导航、待办和操作。当前后端工作台只返回当前项目与已实现操作的 `allowed_actions`，仅本项目 Maker 可见连接草稿数量和入口；Auditor 有本项目连接审计只读操作；Pipeline、准备单、运行及待办概况在工作台接入前明确标为未接入，不伪报零。操作清单不代替后端逐请求鉴权。缺少可用 Secret 引用的连接可保存为未就绪草稿：仅项目 Maker 可读写名称、MySQL 源/Doris 目标类型、主机、端口和数据库名，不接收用户名、密码、Vault 路径或任意扩展字段；不得连通性测试或探查。创建与修改须记录具名操作者、项目、请求追踪标识及审计事件。Auditor 当前只能分页读取本项目连接创建/修改事件的标识、操作者、动作、资源、请求标识和时间，不读取连接详情；完整执行证据待相应记录实现。Maker 提交字段分类及脱敏建议后，由安全审批人在项目待办中确认。
- 本项目 Maker 可创建、读取、修改 `draft_unready` Pipeline 草稿，选择本项目 MySQL 源连接、Doris 目标连接、订单表和用户表，并保存仅供说明的周期文字。连接允许仍未就绪，但草稿不触发排程、探查、生成、冻结或 Prepare。草稿响应明确显示拟议质量阈值与运行预算尚未填写；这两项的字段口径、单位和审批流程须在首次 Prepare 前单独确认，不能据此放行。写入须记录具名操作者、项目、请求标识和审计事件；草稿引用在执行能力实现前重新核对。
- `Checker 1`（数据审批人）审查需求、字段映射、脱敏结果、质量规则及 DAG；`Checker 2`（安全审批人）审查资源范围、分级、预算、Secret 引用和回滚方案。
- **每一次 Commit** 都必须有两名不同的具名数据、安全审批人批准，且两人均不得是该申请的 Maker。`P0–P3` 按已命中的最高风险维度判定，只能增加限制，不能减免双审批。P0 为跨项目越权、Secret 或未授权明文暴露、绕过双审批/受管执行、只读探查发生目标写入等禁止行为；缺少分类依据或证据时返回“无法判定”并阻断，不冒称 P0。P1 为 Commit、L2 实际写入、发布、发布后回滚等目标变更，须执行授权、审计及安全审批人确认风险等级；Commit 与 L2 写入仍须独立双审批，发布沿用本轮授权，发布后回滚依受管回滚规则而无须新双审批；Commit 前复核环境、影响范围与回滚计划。P2 为已授权在线只读探查及有界脱敏样例，须逐次鉴权、范围约束、脱敏与审计。P3 为静态校验及已授权缓存元数据读取，须鉴权和留痕。任一更高风险命中时使用更高等级及其附加控制。
- `Operator` 在审批有效后触发 Commit、监控及受管中断/回滚；`Auditor` 查阅运行、质量与证据记录。项目成员与角色权限必须隔离。
- Maker 对每个 Pipeline 提议质量阈值与读取行数、写入字节、运行时长预算，数据、安全审批人分别审查其职责内的内容；首次 Prepare 前须批准该 Pipeline 的实际数值，缺失则阻断 Prepare/Commit。`Prepare` 冻结输入指纹、资源及影响范围、数据分级、运行预算、回滚方案、审批人和**该 Pipeline 的质量阈值**，不产生外部副作用。拒绝/分流数据处于冻结的允许范围内时，可以通过质量检查并发布。不得将 [PRD](../PRD.md) 脏日志案例中的 20% 当作全局阈值。
- 订单表与用户表均须有主键、可靠变更标记和软删除标记；任一缺失则阻止版本冻结，不以全表读取绕过。模型自动修复仅限不改变业务语义的语法/格式问题；映射、去重、过滤或范围变化由 Maker 重新确认。审批前的“试运行”仅限静态校验与已授权只读安全探查，不得写入目标端。
- 首轮由 Maker 发起 Prepare；后续每轮由 Celery Beat 生成待审 Preparation。每轮在 Prepare 冻结增量水位上界，成功发布后才推进已发布水位；期间新增变化归后续轮次处理。订单与用户所有更新须有可靠、按提交顺序单调递增的变更标记，并能在同一可核实一致的源端快照与上界内读取；迟到、乱序或并发读取不能证明完整性时阻断本轮发布，待连接器能力和数据结果实证后再放行。后续准备单可以创建和审批，但上一轮未执行或未受管关闭前不得先行 Commit。只有 Operator 可受管关闭已拒绝、失效、失败或中断的前轮准备单；须确认无活动运行与发布、记录理由和审计事件，不推进水位。两名审批人对同一准备单并行、独立审批；每轮仍须取得新的双人批准及 Operator Commit。风险无法依据已批准规则判定时阻止 Commit，待补足规则并重新 Prepare。
- `Commit` 由服务端重新核验版本指纹、准备单与审批事实；变化或失效时拒绝执行并重新准备/审批。批准仅对对应冻结事实有效。
- 同一 Preparation 至多产生一次实际 `ExecutionRun`；Preparation ID 是 Commit 的幂等边界，重复或超时重试返回既有结果。另一轮执行必须新 Prepare、新双人审批。Operator 受管中断运行时，后端停止作业、阻止发布并清理未发布暂存与影子结果，保留证据。质量和完整性均通过后，后端在本轮授权内自动发布，无需额外人工发布批准。

## 用户可观察流程与页面

1. **总览工作台**：先选项目，显示当前项目及按角色划分的导航、连接、Pipeline、待办和运行概况；待审批、运行失败与回滚结果提供站内提醒和记录入口。首版不依赖外部消息渠道。
2. **数据源与资产管理**：Maker 为 MySQL 源和 Doris 目标登记受管连接引用；无可用引用时允许保存未就绪草稿，但禁用探查。引用就绪后可做安全连通性测试、只读 Schema/统计探查；未分类字段不返回样本，经安全审批人确认分类和脱敏规则后才显示允许的脱敏样本。界面不得泄露 Secret 或敏感明文。
3. **Pipeline Studio**：自然语言需求结合源表、目标、运行周期等关键项表单；澄清会话可保存为草稿，Maker 离开或重登后从 Checkpoint 续答。展示 EtlPlan、HOCON、DAG、字段映射/Diff、候选历史和校验错误；语义不符时由 Maker 提出修改并生成新候选。冻结前显示关键规则、相对上版差异和阻断项，由 Maker 显式确认；确定性门禁通过后冻结不可变 `PipelineVersion` 和 SHA256 摘要。失败候选不得进入审批。
4. **准备单与审批面板**：首轮人工与后续每轮自动生成的准备单进入统一队列，标明 Pipeline、轮次、来源和状态；详情展示同一冻结事实、证据、质量阈值、风险结论、预算、影响范围及回滚计划。两名具名审批人分别决定并填写理由；拒绝或失效后原单只读，从原单发起修订产生新准备单并重新审批。Operator 在 Commit 前核对版本、审批人与轮次，显式确认；重复或超时请求显示服务端既有结果，不触发第二次运行。
5. **运行中心**：显示 `ExecutionRun`、SeaTunnel 作业、吞吐与日志、有效/拒绝行数、错误码、质量契约命中、预算/硬中断及可解释诊断；自动定期刷新并支持手动刷新，标明更新时间。质量问题展示汇总，只有获授权角色可查看或下载脱敏行级样例。发布阶段与正式版本独立显示；有权限的 Operator 回滚前预览目标、影响并填写原因，页面展示实际结果。提交审批、Commit 或回滚后超时/断线时从对应服务端记录恢复状态，不推断操作失败。
6. **安全治理与 Benchmark**：允许授权人员触发版本化 L0 静态注入、L1 模拟故障、L2 真实链路评测，展示生成准确率与 P0/P1 安全拦截率及对应报告；授权角色可按项目、Pipeline、轮次和操作者追溯审批、执行、发布、回滚及评测证据。达标阈值推迟至版本化测试集确定时单独批准；在此之前只展示指标与证据，不宣称达标。

前端连续操作见 [前端全链路流程](FRONTEND_END_TO_END_FLOW.md)，后端全程交接见 [后端全链路流程](BACKEND_END_TO_END_FLOW.md)，Web API 请求与响应见 [接口契约](API_CONTRACT.md)；页面和服务端的分段操作与失败路径见 [需求生成与版本冻结](FLOW_01_DESIGN_FREEZE.md)、[准备单与审批执行](FLOW_02_APPROVAL_COMMIT.md)、[运行质量与回滚](FLOW_03_RUNTIME_ROLLBACK.md)。这些文件解释本文，不新增或覆盖业务规则。pen.dev 画板及视觉基准留到前端视觉验收阶段，须在页面视觉实施前提供画板并确认样式、响应式与验收口径。

## 技术与安全约束

- 控制面由 FastAPI、LangGraph、Celery、PostgreSQL/Redis 承担；SeaTunnel Zeta 搬运数据，控制面不直接搬运海量业务数据。对话状态、Agent 工作流状态与执行状态分离；Checkpoint 用于跨请求恢复。
- 测试环境的凭据由**真实 Vault KV v2** 管理并由管理员预置。控制面只保存 Secret 引用；经授权的探查/执行 Worker 按最小权限临时物化，界面、日志、报告和审计输出不得出现凭据明文。
- 所有外部副作用经 Tool Broker；`Capability` 使用 Ed25519 签名，绑定工具、主体、环境与制品指纹，有效期 **5 分钟**、单次消费，Replay Guard 拒绝重放。`ExecutionRun` 与 Outbox 命令在同一事务中原子落库，Worker 验签后调用 SeaTunnel。
- `QualityContract` 仅允许行级格式/值异常按错误码分流到错误表，并保留违规原因；安全暴露、Schema、主键、映射及完整性错误直接阻断。`RuntimeSupervisionContract` 冻结读取行数、写入字节数、执行时长预算，监控输出放大比、拒绝率，越限硬中断。质量和完整性报告通过后，后端自动执行 Doris 影子表原子 Swap。
- 具备权限的 Operator 可发起受管回滚，无需新的人工审批。回滚提交须绑定预览操作与所见正式版本；发布与回滚按 Pipeline 串行，版本变化时拒绝旧预览并要求重新确认。发布前清理未发布影子表；发布后保留当前正式版与紧邻上一正式版，以受管反向 Swap 恢复，同时把已发布水位恢复到上一正式版所记录的水位；使基于被撤销版本创建的准备单失效，重放须新 Prepare、双审批和 Commit。操作均需授权、留痕，并防止错误版本被再次发布；更旧版本的自动清理推迟到保留期、存储与批准策略确定后实施。
- Evidence Ledger 对关键事件保存时间、主体、事件、制品哈希、前序哈希与签名检查点，支持链式校验。

### 外部集成边界

| 双方 | 用途与数据方向 | 数据类别 | 责任方 |
| --- | --- | --- | --- |
| 控制面 ↔ Vault KV v2 | 控制面保存引用；授权探查/执行 Worker 临时读取 Secret | Secret 引用、连接凭据 | 管理员预置；安全审批人审查引用；Worker 受控物化；密钥轮换负责人 `UNVERIFIED` |
| MySQL → SeaTunnel → Doris | SeaTunnel 按水位搬运订单/用户增量到 Doris 暂存区；Doris 构建完整影子宽表，质量通过后发布 | 测试环境非敏感业务数据、Schema、作业指标 | Maker 定义映射；Operator 执行；源/目标库长期运维责任人 `UNVERIFIED` |
| FastAPI/LangGraph ↔ PostgreSQL/Redis ↔ Celery | 持久化对话/工作流/执行事实及任务投递 | 需求、版本哈希、准备单、审批、任务状态、审计事件 | 控制面与 Worker；环境运维责任人 `UNVERIFIED` |
| Worker → SeaTunnel Zeta | 凭受管命令提交作业并回传状态 | HOCON、授权上下文、作业 ID、指标 | Operator 监督；连接器配置负责人 `UNVERIFIED` |

## 首版验证与验收

- 在真实组件的测试环境运行**非敏感** MySQL 订单/用户增量样本；展示从需求输入、缺主键去重澄清、恢复、生成、门禁、冻结到 Doris 宽表发布的完整链路，并对照源数据核查字段映射、去重和增量结果。每轮产物为完整可发布版本。
- 验证缺主键/可靠变更标记/软删标记阻止冻结，未分类字段不返回样本，安全审批人在 Prepare 前确认分类及脱敏；Schema 变化仅使受影响字段重审。验证用户更新影响全部历史订单、软删订单从当前宽表移除、软删用户保留订单事实并清空用户维度字段。验证 Beat 每轮只创建待审准备单，按轮次 Commit，仍须新双审批；重复 Commit 不增加实际运行。
- 对同一冻结版本分别验证：Maker 自批、同人兼任两审批、少一审批、审批拒绝、指纹变化、令牌过期及重放均不能引起执行副作用；两名独立具名审批且事实未变化时，Operator 才能成功 Commit。核对 Outbox 与 `ExecutionRun` 的原子记录。
- 分别注入低于与高于该 Pipeline **准备单已冻结阈值**的错误样本：低于阈值时保留错误表/报告且允许发布；高于阈值或超预算时硬中断、不发布。核对行数、错误码、原因与审计事件。
- 分别注入安全暴露、Schema、主键、映射及完整性错误，确认即使行级拒绝率低于阈值也直接阻断；验证质量通过后由后端在本轮授权内自动发布。
- 分别验证运行中受管中断、发布前与发布后受管回滚：中断停止作业并清理未发布结果，发布前清理影子表，发布后恢复上一正式版本及其已发布水位；验证并发发布/回滚串行、旧预览失效、重复回滚返回同一操作结果、旧准备单失效，以及正式表内容、权限和证据链。验证水位只在成功发布后推进，回滚后重放必须新 Prepare 与双审批。
- 运行版本化 Benchmark，输出生成准确率与 P0/P1 安全拦截率及可复核报告；L2 若产生实际写入，仅在隔离的非敏感测试资源执行，且仍须 Prepare、双审批与 Operator Commit。达标判定在阈值确认后才能执行。页面、实际服务、数据结果和报告均需人工验收，技术检查不等于用户验收。
- 逐角色验证先选项目及项目隔离、未就绪连接草稿的探查阻断、字段分类待办与脱敏样例权限、澄清续答、候选重生成及冻结确认；核对每轮准备单、独立审批和重复 Commit 的页面状态与服务端事实一致。验证自动／手动刷新、质量明细权限、发布版本、回滚预览，以及提交后断线恢复和站内待办直达记录。
- **待验证参考测试负载，非正式验收阈值**：基础档为订单存量 100 万行、用户存量 10 万行、每小时变化订单 1 万行和用户 1000 行，按小时运行并观察 15 分钟内完成；压力档为订单存量 1000 万行、用户存量 100 万行、每小时变化订单 10 万行和用户 1 万行，按小时运行并观察 30 分钟内完成。观察范围覆盖提取、暂存、受影响历史订单重建、质量判定与发布。实际业务负载、环境规格、容量验收正式门槛和实测结果均为 `UNVERIFIED`，这些数字不得用于宣称达标。
